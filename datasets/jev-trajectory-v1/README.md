# Jev 双截图时序判定数据集 v1

从已有防御实验、VisualWebArena 和 AndroidWorld 轨迹中摘取的 **1,818 条**监督样本。给 Jev 两张有序原图和含实际动作的原生提示，判断第二张图是否已经显示该动作的结果。共用到 **2,032 张原始 PNG**。没有新跑交互、生成截图、交换图片制造负例，或以历史模型回答作为标签。

| --- | ---: | ---: | ---: |

另附 [train-balanced.jsonl](train-balanced.jsonl)：只取训练集中的 79 条 NO，再选 79 条真实 YES。两类各含 51 次输入文字和 28 次点击，优先匹配同一初始截图与动作。适合做首轮平衡对照；它不覆盖滚动、返回等其他动作，也不能与训练集拼接后重新计数。[contrast-index.jsonl](contrast-index.jsonl) 列出了 28 组同一集合内**第一张图、实际动作和 prompt 完全相同**，但候选图分别支持 YES 和 NO 的例子。

## 一条样本怎样读取

JSONL 每行只有 `images`、`prompt`、`label`。图片路径相对于 JSONL 所在目录；解压后保持 `images/` 与 JSONL 同级即可。正式文件直接保存完整的英文原生 prompt，不需要自行拼接或翻译。

- `images[0]` 是发出该动作前，执行方实际接收的上一张完整截图；受控实验中是已接纳的初始帧。早期浏览器和手机轨迹用有归档交付记录的原图，不假定它们曾经过 Jev。
- `images[1]` 是同一次动作后实际取得且交付的候选截图。图像字节与归档摘要一致；标示点击位置的圆圈只出现在审图材料里。
- `prompt` 包含原生状态说明、实际分发的动作 JSON、固定问题及其两个选项；`label` 是大写 `YES` 或 `NO`。全局 system 指令见 [protocol.json](protocol.json)。原生 API 的结构化请求由既有 builder 生成，不能再把整段导出 prompt 二次拼入 state。原生 readout 中 A 对应 YES、B 对应 NO。

例如，[service-type-defense 的两条实际样本](example-oak-avenue.jsonl)共享同一张[动作前原图](images/63aae8110319db3475191ea68d1469093bc5531f834cefcdc2ae777bd8f09bc7.png)，动作完全相同：`{"text":"Oak Avenue","type":"type"}`。

| 同一次输入动作后的候选帧 | 应输出 |
| --- | --- |
| [早期帧](images/63aae8110319db3475191ea68d1469093bc5531f834cefcdc2ae777bd8f09bc7.png)：Address 栏仍为空 | **NO** |
| [结果帧](images/7330363fbe8c82c577fe2b6628fd345be28d964733ba08873d549713b5f78752.png)：Address 栏已出现 Oak Avenue | **YES** |

在 NO 行中，两张图的字节相同，来自两个不同的真实采集事件；在源轨迹中，早期帧的 capture ID 是 `82d12f5f85d5492c9f52527dd7dcb8c0`，结果帧是 `137b3e00091647d5a85cad81cd8dd76e`。日期、采集时机、标签、URL 和审核理由不会作为附加字段喂给模型。

## 标签依据与可追溯性

**YES**：界面中与动作相关的部分已经显示结果。任务整体不一定成功；明确显示的失败反馈也是结果。重选已明显激活的选项，若其状态清楚可见，也可以是有证据的无变化操作。**NO**：相关结果仍未显现、目标留在先前状态，或只显示了不相干的变化。不会仅因图像相同就标 NO，或仅因图像不同就标 YES。拿不准的样本不进监督集。

| 来源（去重后保留的代表样本） | YES | NO | 依据 |
| --- | ---: | ---: | --- |
| 受控 scale 实验 | 28 | 28 | 签名截图、动作回执、真实早期／渲染结果和已存的独立审计 |
| 受控 toggle guard／outcome | 13 | 13 | 实际控件结果与旁边控件变化分别判定 |
| 已封存的 Classifieds 多步 GUI 实验 | 152 | 0 | 已执行浏览器动作、真实交付画面及本次逐对视觉复核 |
| 历史 VisualWebArena | 1,348 | 56 | 原生执行及双帧交付日志；页面内容、焦点框、显示文字、滚动位移或视觉复核 |
| 历史 AndroidWorld | 167 | 13 | 原始动作与设备尺寸、前后交付截图、可见返回／滚动结果或视觉复核 |

历史采集中，只接受两侧都能绑定到实际交付原图的步骤；静默丢图、替换图和无法绑定执行的动作不进入这些样本。手机点击从记录的实际像素位置换算为原生 prompt 使用的 0–1000 坐标；原始数值仍在来源记录中。受控实验里浏览器**自己实际渲染**过的白屏和局部内容属于真实候选，和事后替换图分开处理。

历史归档标签部分由可复核的规则生成。例如，页面跳转要同时有成功分发的导航动作、相关路由变化和两张原图中已渲染内容的变化；文字输入须在变化区域识别出新出现的实际字符串；滚动须有多处独特图块同向位移，或同轨迹反向滚动确实恢复了此前画面。仅有执行成功、URL 变化或像素差异均不足以单独定标。另做了一轮模型辅助看图复核，并分层抽查 81 个规则候选。**这不是逐条人工金标或双人盲审。**

[manifest.jsonl](manifest.jsonl) 保存样本 ID、split、相对图路径、摘要、原始动作、标签依据和来源 ID。[provenance.jsonl](provenance.jsonl) 可回查入选样本关联的 **7,372 次**原始观测；重复出现仍只导出一条模型输入。[archive-label-evidence.jsonl](archive-label-evidence.jsonl) 提供历史归档中的证据，例如 OCR 区域、滚动匹配点或返回到的历史帧。[source-index.json](source-index.json) 和 [archive-join-counts.json](archive-join-counts.json) 分别说明来源、封存索引及提取范围。`receipt_valid` 表示该来源相应的动作／截图记录通过核对；只有受控采集使用了此处重新核验的 Ed25519 签名，不能把所有旧日志等同于签名回执。

## 划分、范围及使用建议

训练集包含 Classifieds、scale 和完整的 atelier 布局；验证集包含其余 guard 布局及入选的 AndroidWorld 轨迹；测试集包含入选的 Reddit 轨迹和 outcome 实验。按网站／实验布局及轨迹隔离，不随机拆分相邻帧。同一截图、同一录像事件、同一轨迹和重复输入不会跨训练、验证、测试；去重还考虑原图重编码、只有手机系统状态栏不同、以及相同界面上相距不超过 6 个实际像素的重复点击。重复点击保留一条实际执行过的坐标，不合成平均坐标。

归并后的 7,720 个不同候选中，1,818 条成为训练／验证／测试行；355 条视觉等价输入归并进代表样本，218 条因触及已知回归参考被隔离，另有 5,329 条未取得足够监督证据。工作区保留 `pending.jsonl` 和 `protected.jsonl`，可用于今后复核；它们没有计入正式集，也未放入训练包。3,000 条只是最初的参考规模。

正例占正式集的 93.9%；仅看总体准确率会掩盖对 NO 的误放。建议同时报告 NO 被误放为 YES 的比例、YES 被误拦为 NO 的比例，并区分早帧和无关控件变化。验证和测试分别只有 17 和 14 条 NO，适合做回顾性对照，不能当成新采集的盲测。

[validation.json](validation.json) 记录文件摘要和校验结果。逐行核对了双图顺序、原图 SHA-256、标签以及与原生 Encoder.messages 生成的用户文本一致；现有 temporal_head.py 的 check 命令也已通过。构建过程中没有启动模型训练。
