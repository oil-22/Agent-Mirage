# Jev 截图核验：从第一批标注到第一个分类头

适用于本项目的 `perplexity-ai/pplx-decider-flash-v1.2`（4B，revision `9ff7cf9838e59df461c276b7699d56b244d2af58`）。[完整 GUI 协议](../jev-gui-paired-20261122/PROTOCOL.md)中，Flash 单图判断画面是否可读；[双帧实验](../jev-temporal-gate-20261122/Jev双帧旧帧防御实测.md)额外判断“给定已发出的动作，其结果是否已在当前截图中可见”。这个起步包只训练后者，沿用[原双帧提问与坐标格式](../jev-temporal-gate-20261122/temporal_request.py)。

## 1. 一条标注对应一张候选图；采样单位是一次动作

以正常使用的搜索、表单、分页、弹窗和设置开关为来源。记录上一次放行的完整 PNG，**实际执行一次**原生动作，再在同一页面收集 2–4 张带各自采集回执的真实候选 PNG；不要为了得到第二张图再点一次。覆盖自然快速和延迟更新；通过浏览器回执和页面事件交叉核对采集时点，但以实际可见结果裁定标签。快速轨迹可能只有已更新图，不要造一个“早拍”来凑对。已见实测只作回归，新训练样本从新的事件、数据内容和页面家族采。

| 情形 | 标签 | 判定依据 |
| --- | --- | --- |
| 输入后目标字段出现指定文字；翻页只更新页码、范围或少量行；目标开关状态改变 | YES | 即使变化很小，目标已经给出了结果。 |
| 搜索返回明确的空结果；点击后显示与本次操作对应的权限拒绝 | YES | 成功与否是业务问题；可见的失败也是动作结果。 |
| 仍是动作前内容，或目标结果还在加载 | NO | 当前不能把这张图作为已经更新的结果交给主模型。 |
| 焦点环亮起、旁边开关改变、无关状态栏刷新，目标没有结果 | NO | 有像素变化，但变化没有回答这次动作。 |
| 同样的两张图既可能来自合法无变化，也可能是早拍，且没有可见依据 | null | 单列。另有可信页底等依据时走现有旁路，不能算作模型从图中判对。若边界已清楚画在图中，按固定提示单独裁定。 |

先收 **30 个动作事件**，两人只看图对和实际动作，独立标注并写一句可见依据；意见不同再用原始采集记录复核，仍不确定保留 null。口径稳定后扩至 **200–300 个新事件（约 400–1,200 个候选，去重前）**，这是试点预算。不同站点、模板、目标位置、动作类型和等待时长都要尽量含正负两类。尤其多收真变化很小的正例和相邻控件变化的负例；验证和盲测另保留接近实用分布的样本，不能只挑原模型错的。公开的普通 GUI 截图可以补单图可读性，只有带真正相邻帧、已执行动作和可复核结果的样本才能补双帧标注。

**文件格式。** [examples.regression.jsonl](examples.regression.jsonl) 的每一行都是完整实例，5 行对应 3 次已见动作。新建自己的 `fresh.jsonl`，每行保留：

- 模型可见：`before_png`、`action`、`candidate_png`，以及服务原有固定提问。PNG 路径相对 JSONL；点击坐标沿用原生 0–1000 归一化坐标。训练服务仅收到图片内容和动作，不收到文件名。
- 监督：`label` 取 `"YES"`、`"NO"` 或 JSON `null`；`reason` 写清画面哪里变了。可加两人的独立标签、复核人和理由。不要拿旧 Flash 的概率、27B 的回答、任务最终得分当标签。
- 来源：`sample_id, family_id, task_id, trajectory_id, event_id, capture_id, before_sha256, candidate_sha256, receipt_valid, phase, split`。ID 在整份文件中使用有命名空间的稳定值；同一次动作必须复用同一 event_id。phase 取 early、settled、unrelated、no_change 或 unknown，表示已核对的来源/场景，不会拼进提示。可保留回执路径、目标模块、站点和标注人供追溯。脚本检查标注中声明的 receipt_valid；原始回执的真实性仍由现有采集流程验证。

**切分。** 建议用约 70%/15%/15% 的独立组做 train/val/test，优先保证独立性和验证、盲测中各种关键标签的覆盖，比例次之。先合并共用页面模板或高度相似的站点/任务，再整轨迹切分。固定任务的两臂、同次动作的复拍、相同/近似页面不能跨集合。模板太少就留一整个模板家族做外测，并说明泛化范围。脚本检查已登记的分组和像素文件的精确 SHA；相同像素的不同编码、近重复布局须用感知去重或人工归组。独立事件数与 PNG 数分别报告。旧公开回归索引和本包示例的图片不能改名充作新数据。

## 2. 训练和对照

在本目录运行下面的命令。`check` 只需要 Python 3.11+、NumPy、Pillow。本包使用项目里的原请求构造器、回归索引和 checkpoint 清单；移到训练机时保留同样的相对目录结构。实际 `fit` 和 `test` 使用已有的 Flash 原生 CUDA 环境、已下载的完整 checkpoint，以及新采集并正式标注的 `fresh.jsonl`。把命令中的 `PATH_TO_FLASH_CHECKPOINT` 换成本机路径。

```text
python temporal_head.py check examples.regression.jsonl
python temporal_head.py check fresh.jsonl
python temporal_head.py fit fresh.jsonl --checkpoint PATH_TO_FLASH_CHECKPOINT --head temporal-head.json
python temporal_head.py test fresh.jsonl --checkpoint PATH_TO_FLASH_CHECKPOINT --head temporal-head.json
```

1. 原生 Flash 使用 `fast=False`。脚本在原生 `decider.logits([request])` 的同一次前向，取送入 `readout` 的决策标记向量 h 和原始 YES、NO 分数。保留原始图像顺序、处理器、注意力掩码、选项顺序及无 KV 缓存的路径。
2. 冻结全部原模型，只训练一个零初始化向量 w。新分数为 `(logit_yes - logit_no) / 原生温度 + h·w`。以 YES=1、NO=0 计算带 L2 的二元交叉熵；同一事件的所有候选合起来占一个事件的权重。特征在内存中提取一次，分类头在 CPU 上拟合。`--l2 0.01` 为起点；如比较少量不同的正则强度，只看验证集。若不改分数只改阈值，会保留原来的样本排序。
3. 验证集须同时有已显现 YES、可信的真实早拍 NO、其他 NO（例如无关控件变化）。脚本为原分数和新头分别选阈值：在两类 NO 的误放次数均不超过原生默认值的前提下，尽量少误扣 YES。这个约束只在验证数据上成立。头文件保存权重、阈值和输入版本；一个训练候选使用一个新文件。冻结最终候选再运行一次 test，勿据此回调阈值。
4. 原生头、阈值对照、新头在相同图对上比较。打印的三项是“错误数／该类总数”：真实早拍误放、其他 NO 误放、YES 误扣。正式报告另按动作类型/页面家族分层，并以任务或轨迹为单位重采样给不确定性。负例太少时即使观察到 0 次漏放，也不能当作真实风险为零。
5. 只有在新页面上确认线性头还分不开关键对照、且有足够多样本时，再试视觉塔冻结、后几层语言层 LoRA（可从 rank 8 开始，按显存定 batch，验证集早停）。使用同一原生多模态编码，在可反传的 backbone + marker 读出路径上训练；`reference_logits` 有 `inference_mode`，`decide` 也不是训练入口。比较 LoRA 和线性头时用完全相同的划分和标注。随单图路径请求时不加载这个双帧增量。

最后在新浏览器轨迹做配对验证：单图流程、加原生双帧、加微调双帧。统计第一次早拍有没有真的进入 27B、第一次正常图是否误扣、同一动作不重做的复拍恢复率、等待中位数/P95。缺图和交付图与回执不一致由确定性检查处理，不能记为 Jev 检出。总体 Mirage 是否下降需另对完整任务轨迹独立标注。

若研究目标是**只改现行单图质检**，单独采“当前完整 PNG → 是否可读”的数据：正常稀疏页、页脚、空结果页和清晰错误页对照真实白屏、未渲染或不可读画面。缺失文件不进图像分类器；仅凭单张清晰截图无法判断是不是上一动作的旧画面。使用单图原提示和独立头，不能直接使用本脚本的双帧数据或权重。

本包交付的是标注样例和可运行的实验入口，不含已经微调的权重。原有[模型微调方案](../jev-verifier-finetune-20261122/Jev核验器微调方案.md)、[96 条受控轨迹](../jev-defense-scale-20261122/Jev截图防御96条规模实验.md)和[开关误拦实测](../jev-toggle-outcome-20261122/Jev误拦修复36条配对实验-20261122.md)可作为设计依据。
