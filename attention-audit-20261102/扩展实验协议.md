## 冻结的范围

1. 历史窗口与时机：从已有未注入 OSWorld 对照归档中，选取原九任务以外所有至少 15 个决策的不同任务 UUID，共新增 10 条、总计 19 条。应用内按任务 UUID 排序；同一 UUID 优先较新的原协议，不把重复运行计作独立任务。早中晚按决策索引 10%／50%／90% 分位，交叉无历史／最近两轮／完整文本历史，以及正常图／白屏／缺图／上一实际帧。新增每模型 360 配置，共 1,080；原 972 配置复用。
2. 四注入：新增十条轨迹的三位置、三历史窗口各补一个控件区域遮罩配置，每模型 90，共 270。与相同前缀的四条件构成完整五条件配对。新集合中 8 个任务 UUID 未出现在旧四注入严格配对集合，另外 2 个是已有任务在新增归档轨迹／时点的观测，不能冒称十个都新增了独立任务 ID。
3. 遮罩版本为 visible-control-regions-v2：助手根据 30 张源截图预先标注可见工具栏、侧栏、窗口控件、对话框表单区域，保留区域内原像素、区域外纯白；保留区域本身可能包含控件文字和值。是矩形控件区域遮罩，不是精确按钮分割，也不是旧原生遮罩算法。不得直接合并两个版本的效应。标注、像素边界和保留比例完整保存；生成后逐图检查。未将旧 VWA 的网页局部渲染记录冒充正常图与遮罩的同源像素配对。
4. 来源实验：14 条不同 VWA 任务轨迹，在原 27B 缺图 step 2 的真实状态断言处设置原样／撤回为不确定／语义等价改写三条件；每条固定后续 step 3、5、8（间隔 1／3／6）的实际请求、动作历史与截图。三模型各 126 配置，共 378，补足原先仅两个案例的来源分析。选样依据可明确定位、可编辑的状态句，未按新输出、注意力或动作变化挑选。三种文字版本必须通过三模型原生请求 token 长度匹配和编辑范围审计，才进入正式推理。

## 解释边界

- 来源真值单列：对 14 张源时刻捕获截图的助手视觉复核为 3 条断言与截图矛盾、8 条得到截图支持、3 条视觉无法可靠确认。不能把这 14 条都叫 Mirage 阳性。按这三个层次分别报告，支持组用作对照，矛盾组才用于错误源案例分析。不是独立人工盲标，不估发生率。
- 撤回表示“不确定／不能确认”，没有注入真实搜索结果、没有改变后续派生状态或执行环境。行为变化不是任务恢复证明。
- 来源实验保留源句之后的归档回复与动作，其中可能已重复／传播原断言。它估计的是给定固定后续历史时编辑早先一句话的局部敏感性，不是重新生成整条历史后的传播总效应；后续历史可能稀释或保留原错误。
- 历史窗口同时改变内容与长度，不是纯长度因果对照；历史增长与图像、任务状态变化仍需区别。
- 以任务为重采样单位报告配对差值；同一轨迹的多个时点不当独立样本。新十任务单列为扩展集，再给出与旧九任务合并的十九任务结果。
- full-attention 语言层 softmax 的首输出 query 与动作文本 query 分开；不是完整模型因果归因。缺图图像份额的零为结构性零。不同 tokenizer、图像 token 数和控制区域覆盖率必须保留。

## 运行与核验

新增 GPU 推理只在 3090 进行。沿用已校验的原生模板、BF16／SDPA、greedy、2048 输出上限与包含 tokenizer EOS 的停止设置；不执行 GUI、不调用付费 API。未使用 GPU 1，保留其现有无关进程。

每批先核验注意力采集开关前后完整输出 IDs 和逐步完整 logits 相等，再正式采集；保留实际输入 IDs、来源 token mask、逐 query×层×头张量、完整回复、停止状态和 SHA。主批现已通过三模型各两请求预检。来源另做 CPU 原生输入预检，再做 GPU 真实快照预检。所有配置完成后核验索引与张量、审计源句修改范围、报告截断／失败与精确请求复用。

预设生成上限导致的截断属于成功采集但回复删失，不按技术失败计，也不根据已见结果延长上限重跑。首 query 仍完整可用；完整回复行为率与动作 query 的正式配对分析排除截断，并保存全部截断文本与名单。终局“全部配置完成”和“全部回复自然结束”分开报告。
